# 到期那天 In Time

> **家庭开封保质期与临期看板** · In Time · 到期那天，还来得及。
>

---

## 一、产品是什么

目标用户常常忘记冰箱冷冻室、冷藏区、药箱、化妆品里东西的开封时间。「到期那天」让用户拍照或手动录入物品名称、开始使用日期、保质期（天/月/年），首页即呈现**红（已过期）、黄（临期）、绿（安全）**三色状态卡片，一眼掌握全家物品的保质期；另有两个不参与红黄绿到期语义的莫兰迪蓝辅助状态：「保修」（只填保修结束日）与「备忘」（旧版位置备忘或无到期/保修信息的维保记录）。

**核心原则**

- 纯原生微信小程序（WXML / WXSS / JavaScript / JSON），无 uni-app、Taro、React、Vue、TypeScript，无第三方 UI 框架与图标库，无远程 CDN。
- **纯本地数据**：无云开发、无后端、无数据库、无登录、无网络请求。记录、设置、日历导入状态全部保存在 `wx.setStorage` 本地缓存；照片持久化在 `wx.env.USER_DATA_PATH`。
- 拍照仅作为**封面图片**，名称与保质期由用户手动确认，不做 OCR，避免离线场景下的虚假识别。
- 基础库最低兼容 **2.15.0**，日历能力全程做兼容性检测与降级。

**业务规则**

- 新建至少填写保质期（或开始使用后可用天数）、保修结束日期、完整维保信息之一；维保需上次维护日期与周期，自定义周期为 1–3650 整数天。位置可选。三栏可以同时填写，不新增持久化类型字段，旧版位置备忘仍可编辑保存。

- 到期日 = 开始使用日期 + 保质期（天/个月/年，日历法）；若填写了「开始使用后可用天数」(openedDays > 0) 则优先按它计算。`daysLeft` = 到期日相对「今天 00:00」的自然日差。
- `daysLeft < 0` 红色已过期；`0 ≤ daysLeft ≤ warningDays` 黄色临期；否则绿色安全。
- 文案：今天到期 / 明天到期 / 还剩 X 天 / 已过期 X 天。
- 首页排序：已过期 → 临期 → 按到期日由近到远。
- 到期状态**永不落库**：所有页面每次打开都通过 `utils/record.js` 的同一套函数实时计算。用户主动处理产生的归档标记和处理历史则保存在本地。
- 日期统一用 `new Date(y, m-1, d)` 构造本地时间，绝不使用 `new Date('YYYY-MM-DD')`，规避时区偏差；闰年与跨月由 Date 构造器与校验逻辑处理。

## 四、在微信开发者工具中导入

1. 打开**微信开发者工具**（建议最新稳定版）。
2. 选择「导入项目」，目录指向本仓库根目录（包含 `project.config.json` 的目录）。
3. AppID：仓库已配置正式 AppID（`wx391039438b36bcb8`），如需换号自行替换 `project.config.json` 中的 `appid` 字段。
4. 确认「详情 → 本地设置」中基础库选择 **2.15.0 及以上**（日历 API `wx.addPhoneCalendar` 自 2.15.0 起支持；当前配置为 3.17.1）。
5. 点击「编译」即可运行。日历真机效果请使用**真机调试/预览**（模拟器对系统日历写入支持有限）。

## 五、可复现测试步骤（对照验收标准）

1. **空白新增**：首次启动选「从空白开始」→ 点右下「＋添加物品」→ 录入冷冻食品（分类选「冷冻」）→ 保存 → 返回首页立即看到绿色「安全」卡片。
2. **过去日期**：新增药品，把开始使用日期改为 40 天前、可保存 30 天 → 首页显示红色「已过期 10 天」；再建一条开封 25 天前、可保存 30 天 → 显示黄色「明天到期/还剩 X 天」。
3. **阈值切换**：我的 → 临期阈值改为 3 天 / 14 天 → 返回首页，黄绿状态与统计数立即按新阈值变化。
4. **叠加筛选**：物品页输入关键词 + 选分类「药品」+ 状态「临期」+ 排序「到期最早」，验证结果同时满足四个条件；再下拉刷新，四个条件应保持不变。
5. **照片持久化**：新增物品时拍照作封面 → 保存 → 编译重启小程序 → 首页与详情页照片仍显示。
6. **文件清理**：编辑物品替换/移除照片，或删除记录 → 照片文件不残留（实现上调用 `FileSystemManager.unlinkSync` 删除 USER_DATA_PATH 下对应文件）。
7. **日历权限时机**：只有点击详情页「添加到手机日历」或批量页「导入 N 条」后才会出现授权弹窗；页面加载时绝不申请。
8. **拒绝/不支持降级**：拒绝日历权限（或低版本基础库）→ 弹出解释/降级提示 → 返回后看板、录入等主功能全部正常。
9. **批量导入**：我的 → 批量导入日历 → 勾选若干条 → 导入 → 观察「正在导入 X / N」进度 → 结束后显示「成功 X 条，失败 Y 条」；已导入记录默认不再勾选（跳过开关默认开）。
10. **数据恢复**：下拉刷新、切换 tabBar、重新编译启动 → 数据均从本地缓存恢复。
11. **深色模式**：我的 → 外观切换「深色/浅色/跟随系统」→ 各页面无低对比度文字、无溢出错位。
12. **完成维护（核心流程已用户核验，2026-09-20）**：打开设有维护周期且上次维护不是今天的物品 → 维护卡「已完成维护」→ 先取消，日期应不变 → 再确认，上次维护变为今天、下次维护按原周期重算，按钮显示「今天已记录维护」；返回列表并重新进入、重启后结果仍保留。当天不重复记录；补记其他日期用「编辑物品」。用户确认上述流程与功能正常，另提深色外观反馈，按第 15 项复验。
13. **日期用语（2026-09-21 用户反馈暂未发现问题）**：新增/编辑、快捷反推、详情、备忘卡片与新导出的日历描述使用「开始使用日期/已使用/开始使用后可用」，购买字段为「购买日期」；旧记录日期、到期结果保持不变，既有系统日历事件不改写。

## 六、微信平台能力限制说明

### 「历史上的今天」数据来源与再生成

- 本地数据来源于 GitHub 开源项目 [PrintNow/TodayInHistory](https://github.com/PrintNow/TodayInHistory)（数据源于维基百科），经 [tools/convert.js](tools/convert.js) 清洗生成：剔除战争、政治、暴力、灾难类敏感条目，每天保留 5~10 条，共 366 天 / 3505 条，总体积约 295KB（占主包 2MB 的 15% 左右）。
- 注意：微信基础库的 `require()` 不支持 `.json` 文件（会报 `module not defined`），数据文件以 `.js` 模块形式输出（`module.exports = {...}`）。
- 如需更新数据：下载该项目 `history_in_today.json` 放入 `tools/` 目录（仓库内已有一份），执行 `node tools/convert.js` 即可重新生成 `miniprogram/data/history/*.js`。
- 可选在线增强：在 `utils/history.js` 顶部 `API_CONFIG` 填入聚合数据 / 天行数据 key 并开启后，将优先请求在线接口（需在小程序后台配置合法域名）；接口失败自动回退本地数据，不影响任何功能。

### 其他平台限制

- **日历写入的手势链限制（安卓）**：微信要求 `wx.addPhoneCalendar` 必须在用户点击手势链内发起。安卓端批量导入时，第一条写入调起系统日历后手势链即被消耗，自动续写下一条会报 `fail can only be invoked by user TAP gesture`。因此安卓端批量导入采用「逐条弹窗确认续写」：每写完一条弹窗展示进度，用户点「继续写入」发起下一条；中途可随时「停止」，已写入的日程保留。iOS 端无此限制，自动串行（间隔约 800ms）。
- **iOS 页面拖拽锁定**：全部 12 个页面已配置 `"disableScroll": true` 并用内部 `scroll-view` 承担纵向滚动，彻底避免 iOS WebView 页面整体可上下左右拖拽、内容偏移与双向滚动条问题；首页、「今天」与物品三页的下拉刷新由 scroll-view 的 `refresher` 实现，并带自定义文案反馈（下拉刷新 → 松开立即刷新 → 正在刷新…）；「今天」页下拉完成后提示「内容已刷新」（「我的」为设置页，刻意不设下拉刷新）。下拉刷新不联网，仅重读本地缓存并按「今天」重算红黄绿状态；它的真实价值在于小程序长时间停在前台跨过零点时（此时不会触发 `onShow`，状态会停在昨天）可手动重算。详见 `AI_CONTEXT.md` 决策 5.1。
- **日历只写不读**：`wx.addPhoneCalendar` 仅支持「添加」日程，微信不返回事件 ID，因此应用**无法删除、更新或查询**已写入系统日历的日程；详情页与批量导入页均已明确提示「已添加的日程请在系统日历中管理」。重新导入可能产生重复日程，已做明确告知。
- **日历 API 时间单位**：`startTime` 与 `alarmOffset` 均按**秒**传入；事件固定在到期日上午 09:00（本地时间）。
- **本地缓存容量**：`wx.setStorage` 单 key 上限约 1MB、总量约 10MB（平台差异），照片走文件系统不占用该额度；记录体量（家庭场景）远小于上限。
- **分享（发送给朋友 / 分享到朋友圈）**：看板、物品、今天、详情四个内容页开启（胶囊「…」菜单出现对应入口；朋友圈需基础库 2.11.3+）。因数据纯本地存储，分享落地页不携带记录 id（朋友设备无对应记录，避免「记录不存在」）；详情页分享标题携带物品状态作谈资、落地页指向首页看板。表单与设置页（新增/编辑、批量导入、我的）不开分享。
- **缓存生命周期**：卸载微信、清理小程序缓存、更换设备都会丢失数据，「本地数据说明」中已向用户明示。
- **模拟器限制**：模拟器上相机/相册与系统日历行为可能与真机不一致，建议用真机调试验证第 5、7、9 项。
- **深色模式**：主题单一事实来源为「跟随系统 / 浅色 / 深色」偏好，由 `app.js` 解析为生效主题；页面级 CSS 变量换肤 + `wx.setNavigationBarColor` / `wx.setBackgroundColor` 动态着色，自定义 tabBar 由组件自身深浅色类驱动（不使用原生 `wx.setTabBarStyle`）；`wx.onThemeChange` 低版本不可用时不接收系统主题事件。`themeReady` 门控用于首次初始化；安卓手动切主题后首次切到已访问 Tab 仍有整页旧色闪烁，根因待定位，不能统称平台限制（见 `AI_CONTEXT.md` 决策 6.6）。
